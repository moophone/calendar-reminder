## 1. 目标

- 首页去掉常驻的"选择一件事查看详情"区域，改为**点待办看详情**。
- 新增**常驻待办窗口**：不点进日期就能看到所有待办（长期一直挂、短期临近出现）。
- 待办分**长期 / 短期**两类（全部手动指定）。
- 全部待办有**倒计时**（复合单位：X月X天 / X周X天 / X天X小时 / X小时；月按自然月，规格见 §3.1）；短期必填目标日期，长期可选。
- 导入解析改为**算法 + AI 融合管线**，去掉现有 4 个单选项（已核对 ui.py：AI 全自动 / 按编号分组 / 每行一件事 / 整段合并）。
- 整体 UI 换**暖纸手账**风格。
- 维持：纯本地离线、PyQt6、无新增第三方依赖（模型走 llama-server.exe HTTP）。

### 2.1 小日历框（左上）

## 3. 长期 / 短期待办

| | 长期 | 短期 |
|---|---|---|
| 归属 | 手动指定 | 手动指定（默认） |
| 目标日期 | 可选；有则显示倒计时与日历圆点，无则显示"未设目标日"、排序置最后 | 必填（截止日） |
| 常驻窗口 | 一直显示 | 距目标 ≤7 天才出现 |
| 提醒 | 每天首次启动软件时弹一次（同日多次启动只弹一次） | 进入 7 天窗口开始提醒，当天最强；沿用现有提前 1/3 天参数 |
| 完成 | 归档不删除 | 归档不删除 |

- 类型**只能手动指定**，程序不猜。
- 数据库：`tasks` 表加列 `task_type TEXT DEFAULT 'short'`、`last_notified_at DATE NULL`；`due_date` 允许 NULL（长期可无目标日）。旧数据迁移后 `task_type='short'`、`last_notified_at=NULL`，用户手动把 SAIS(id=15) 等改长期（详情卡/编辑对话框提供切换）。
- 迁移补索引：`CREATE INDEX IF NOT EXISTS idx_tasks_type_due ON tasks(task_type, due_date, is_archived);`（覆盖右侧面板主查询 `WHERE is_archived=0 AND (task_type='long' OR due_date<=today+7)`）。
- **长期无目标日的行为**：排序置最后；日历无圆点；详情卡倒计时显示"未设目标日"；不弹每日启动提醒（无"到期"概念）；`due_date/due_time` 均为 NULL。
- **"每天首次启动"实现**：启动时扫描长期任务，仅 `last_notified_at < today` 才弹提醒，弹完写回 `last_notified_at = today`；短期提醒沿用现有参数，不写该字段。
- 倒计时由 due_date/due_time 实时计算，不落库。

### 3.1 倒计时算法规格（实现前先写单测，防止各分支漂移）

- 输入 `start`、`end`，`end >= start`；输出按量级选择：≥1月→"X月X天"；≥1周→"X周X天"；≥1天→"X天X小时"；<1天→"X小时"。
- **自然月加法**：逐月推进保持"日"不变；目标月无该日取该月最后一天（`2026-01-31 + 1月 = 2026-02-28`）。
- **月天拆分**：`n=0; while start+(n+1)个自然月 <= end: n+=1; 余 = end - (start + n个自然月)`。
- 单测必须全过：`2026-10-09→2027-03-01 = 4月20天`；`2026-10-09→2027-03-15 = 5月6天`；`2026-01-31→2026-02-28 = 1月0天`；`同日 = 0天`；`+1天 = 1天`；`+7天 = 1周0天`；`+8天 = 1周1天`；跨年、跨闰年各一条。

## 4. 算法 + AI 融合管线（导入解析）

解析对话框：**只留一个"智能解析"按钮**，去掉现有 4 个单选项。流程四阶段，核心原则——**模型只做分组/命名/摘要/选择，算法做全部日期、时间、重复的枚举与换算**（详细规格见《AI算法融合参考.md》§0 最终方案）。

1. **P0 算法先行**（毫秒级）：规则引擎逐行+整段合并双模式自动择优；额外产出句子编号 `S1..Sn`、日期候选 `D1..Dn`、时间候选 `T1..Tm`、重复候选 `R1..Rk`（歧义日期只给最优解析并标 `ambiguous`，裁决归算法），每条规则事件记录 `source_sentences`。规则结果立即上表，用户不等。
2. **P1 AI 解读**（后台 5~8 秒）：模型只输出 `sentences:[Sx]`、`title`、`date_id/time_id/recur_id`（从 P0 候选里选或 null；单条事件最多选 2 个 date_id，超出拆条）、`detail`。**禁止模型输出日期数字**。输出 GBNF 语法约束为主 + JSONL 为备（llama-server 启动探针验证 grammar 生效，失败自动降级）；temperature=0，失败重试一次，整体失败直接丢弃 AI 结果。
3. **P2 匹配合一**：句子重叠为主锚点——`overlap = max(Jaccard, |交集|/min(两边句数))`（兼容"AI 合并 3 句 vs 规则抓到 1 句"）；标题 bigram+编辑距离为辅；全局一对一。双方都有→规则日期+AI 标题/备注，**但用户在 P1 期间改过的字段不覆盖**（每行记 `user_edited`）；规则独有→保留；**AI 独有分两档**（见 UI 行为）。
4. **P3 终检**：SID 越界丢弃、白名单校验、长度硬切、空标题丢弃、过去日期/换算失败标黄阻断入库。长文本按句子分块（内容 hash 去重，合并条件收紧），不截断。

UI 行为：
1. 规则结果先亮（P0 上表）→ AI 后台跑，期间表格可编辑、可提前导入（不等 AI）；
2. AI 完成后原地更新，变化单元格高亮 2 秒；状态栏显示"AI 已优化 N 处（跳过用户已改 M 处）"，分块时显示"AI 解析中 x/y"与耗时；
3. **AI 独有条目分两档**：有有效 date_id + 日期在未来 + sentences 非空 → 自动勾选、标黄"AI 新增，请复核"；否则默认不勾选、标红"AI 新增，需人工确认"；表格顶部给"全选/全不选"；
4. **取消语义**：解析中"智能解析"按钮变"取消 AI"，点击后取消 worker、保留 P0 规则结果、状态栏提示"AI 已取消，保留规则结果"；重新发起前先取消旧 worker；
5. 导入表格新增"类型"列（长期/短期下拉，默认短期）；
6. **预加载**：软件启动后低优先级线程静默预启动 llama-server，消除首次点击的约 5 秒等待。

## 6. 全局交互规范（新增痛点修复）

**规则：任何窗口/视图都必须有明确、可见的退出方式；不允许只摆"确定/删除"这类动作键。**

- 详情卡：右上角加 **× 收起**钮，点击回到"自动选中最近到期项"；Esc 同效。
- 提醒弹窗（无边框）：标题行右端加 **× 关闭**钮（与"知道了"等效）。Windows 约束：flags 用 `Tool | FramelessWindowHint | WindowStaysOnTopHint`；定位用 `QScreen.availableGeometry()` 按光标所在屏幕计算（多显示器不偏移）；`activateWindow()+raise_()` 后确保 Esc 与 × 均能关闭。
- 新建/编辑、导入弹窗：保留 取消 + 标题栏 ×，并确认 Esc=取消、Enter=保存。
- 新做的任何窗口一律遵守本条；无边框窗口必须自带 × 或右键菜单含退出。
