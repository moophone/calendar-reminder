## 二、项目背景与目标

### 2.1 为什么要重设计

v1.0 版本存在以下核心问题：

1. **布局失衡**：原界面将日历放在上方、任务列表在下方，详情面板被挤压在右侧狭长区域，信息密度过高。
2. **点击失效**：任务卡片使用自定义 Widget 嵌套 QLabel，导致用户点击任务文字时无法触发选中事件。
3. **信息层级混乱**：长期任务与短期任务混用同一种卡片形态，用户难以快速区分。
4. **单文件过大**：`ui.py` 已达 68KB，维护困难。
5. **视觉风格单一**：只有一套默认配色，无主题切换能力。

### 2.2 设计目标

- 建立清晰的三栏信息架构。
- 区分不同类型的长期任务。
- 提供可扩展的主题/皮肤系统。
- 保持「暖纸手账」的核心情感基调，同时支持冷色、暗色、自定义等变体。
- 输出可直接指导后续 Qt/PyQt 开发的高保真原型与规范。

### 2.3 用户画像

- 主要用户：大学生、研究生。
- 使用场景：课程作业 deadline、竞赛报名、考试复习、每日习惯打卡。
- 核心诉求：一眼看清「今天要做什么」「什么快逾期了」「长期目标还剩多久」。

### 3.2 选择三栏而非双栏的理由

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 三栏（当前） | 日历、列表、详情并列，空间充足 | 总宽度较大 | ✅ 采用 |
| 双栏（豆包建议：左列表+右日历/详情） | 列表为主导，路径短 | 日历变弱，违背「先选日期再看事项」流程 | ❌ 未采用 |

### 3.3 任务分组策略

中栏任务按紧急度和类型分组，每组带折叠箭头：

| 分组 | 顺序 | 颜色来源 | 显示条件 |
|------|------|----------|----------|
| 逾期 | 1 | `--app-overdue` | `due_date < today` 且未完成 |
| 今天 | 2 | `--app-today` | `due_date == today` 且未完成 |
| 7天内 | 3 | `--app-week` | `today < due_date <= today+7` 且未完成 |
| 长期 · 习惯打卡 | 4 | `--app-long` | `task_type == 'habit'` 且未完成 |
| 长期 · 目标倒计时 | 5 | `--app-long` | `task_type == 'goal'` 且未完成 |
| 普通远期 | 6 | `--app-ink` | `due_date > today+7` 且未完成 |
| 已完成 | 7 | `--app-ink-3` | 已完成（折叠态） |

### 3.4 长期任务分型

这是本设计的核心创新点之一。不是所有长期任务都是「习惯打卡」，必须分门别类：

| 类型 | 业务含义 | 示例 | 卡片形态 | 所需数据 |
|------|----------|------|----------|----------|
| `normal` | 普通待办 | 图书馆还书 | checkbox + 标题 + 倒计时 | `due_date` |
| `habit` | 需要每日/周期性坚持的习惯 | 每日晨跑 3 公里 | 连续打卡条 + 进度条 + 当前连续天数 | `journals` 表记录每日完成状态 |
| `goal` | 有明确目标日期的里程碑 | 全国大学生数学建模竞赛 | 目标标题 + 标签 + 剩余天数 + 目标日期 | `target_date` |
| `registration` | 报名/截止时间类提醒 | 英语六级报名 | 倒计时 + 截止时间 + 标签 | `due_date` + `due_time` |

> **批判性说明**：hy 的 v7 实现把所有长期任务都默认加上「30 天习惯周期」进度条，这对竞赛、报名类事项并不合适。本设计只对 `habit` 类型启用打卡形态。

## 八、数据结构与实现建议

### 8.1 推荐 `Task` 数据类

```python
from dataclasses import dataclass
from datetime import datetime, date
from enum import Enum

class TaskType(Enum):
    NORMAL = "normal"      # 普通待办
    HABIT = "habit"        # 习惯打卡
    GOAL = "goal"          # 目标倒计时
    REGISTRATION = "registration"  # 报名/截止提醒

class TaskPriority(Enum):
    LOW = 0
    NORMAL = 1
    HIGH = 2
    URGENT = 3

@dataclass
class Task:
    id: int
    title: str
    description: str = ""
    notes: str = ""
    task_type: TaskType = TaskType.NORMAL
    priority: TaskPriority = TaskType.NORMAL
    
    # 时间相关
    due_date: date | None = None
    due_time: datetime | None = None
    target_date: date | None = None  # 用于 goal 类型
    created_at: datetime = None
    completed_at: datetime | None = None
    
    # 重复（暂不扩展自定义规则）
    repeat_rule: str | None = None
    
    # 标签
    tags: list[str] = None
    
    # 历程记录
    history: list[dict] = None
    
    # 习惯打卡专用
    journal_entries: list[dict] = None  # [{date: str, done: bool, note: str}]
    
    @property
    def is_overdue(self) -> bool:
        if self.completed_at or not self.due_date:
            return False
        return self.due_date < date.today()
    
    @property
    def is_today(self) -> bool:
        return self.due_date == date.today() if self.due_date else False
    
    @property
    def days_remaining(self) -> int | None:
        if not self.due_date and not self.target_date:
            return None
        target = self.due_date or self.target_date
        return (target - date.today()).days
```

### 8.3 任务分组逻辑伪代码

```python
def group_tasks(tasks: list[Task]) -> dict[str, list[Task]]:
    groups = {
        "overdue": [],
        "today": [],
        "week": [],
        "habit": [],
        "goal": [],
        "future": [],
        "completed": []
    }
    
    for task in tasks:
        if task.completed_at:
            groups["completed"].append(task)
        elif task.task_type == TaskType.HABIT:
            groups["habit"].append(task)
        elif task.task_type == TaskType.GOAL:
            groups["goal"].append(task)
        elif task.is_overdue:
            groups["overdue"].append(task)
        elif task.is_today:
            groups["today"].append(task)
        elif task.days_remaining is not None and task.days_remaining <= 7:
            groups["week"].append(task)
        else:
            groups["future"].append(task)
    
    # 每组内部按截止时间升序
    for key in ["overdue", "today", "week", "future"]:
        groups[key].sort(key=lambda t: t.due_date or date.max)
    
    return groups
```

### 9.2 主题切换 Python 示例

```python
from PyQt6.QtWidgets import QApplication
from PyQt6.QtCore import QFile, QTextStream

class ThemeManager:
    THEMES = {
        "warm": "assets/themes/theme-warm.qss",
        "cool": "assets/themes/theme-cool.qss",
        "forest": "assets/themes/theme-forest.qss",
        "dark": "assets/themes/theme-dark.qss",
        "anime": "assets/themes/theme-anime.qss",
    }
    
    def __init__(self, app: QApplication):
        self.app = app
        self.current_theme = "warm"
    
    def load_theme(self, name: str):
        if name not in self.THEMES:
            return
        path = self.THEMES[name]
        file = QFile(path)
        if file.open(QFile.OpenModeFlag.ReadOnly | QFile.OpenModeFlag.Text):
            stream = QTextStream(file)
            self.app.setStyleSheet(stream.readAll())
            self.current_theme = name
            file.close()
```

### 9.4 关键实现注意点

1. **点击事件捕获**
   - v6 问题：自定义 Widget 内只给 QLabel 设置事件，导致点击文字区域外无效。
   - 正确做法：给整行容器（QFrame/QWidget）重写 `mousePressEvent` 或安装 `eventFilter`。

2. **日历实现**
   - 可用 `QCalendarWidget` 自定义样式，但限制较多。
   - 推荐：用 `QGridLayout` + 自定义 `QPushButton`/`QFrame` 绘制日期单元格，更灵活。

3. **任务列表分组**
   - 用 `QListView` + `QAbstractListModel`，在 Model 中按分组插入「分组标题项」。
   - 或用 `QTreeView` 按分组展开折叠。

4. **三栏布局**
   - 用 `QSplitter` 实现可拖拽宽度。
   - 左栏设置 `minimumWidth=200`，右栏设置 `minimumWidth=300`。

5. **主题切换性能**
   - 切换主题时只调用 `app.setStyleSheet(...)`，不要重建窗口。
   - 自定义皮肤持久化到 `QSettings` 或 SQLite。

6. **弹窗体验**
   - 关闭按钮尺寸 ≥ 40×40。
   - 弹窗打开时捕获 `Esc` 键关闭。
   - 模态弹窗使用 `QDialog.exec()`。

- **布局**：三栏布局（日历+列表+详情），解决详情被挤压问题。
- **点击问题**：任务卡片使用 `QListWidget` 或整行事件捕获。
- **日历点击**：应触发当天视图切换，而非仅高亮。
- **详情面板**：默认不要隐藏，保持状态可见。
- **选中态**：强化视觉反馈。

### 10.2 hy 意见要点

- **完整实现**：交付了 v7 代码包（3810 行），包含 23 个测试。
- **布局**：三栏 + 顶部全局添加框。
- **长期任务**：区分 `ProjectRow`（长期项目）和 `TaskRow`（短期任务），使用 `journals` 表。
- **习惯打卡**：30 天习惯周期 + 进度条。
- **日历圆点**：按最紧急事项着色。
- **接口假设清单**：明确列出需要核对的 storage 接口。

**批判性评价**：hy 的实现最完整，但存在过度泛化问题（把所有长期任务都当作习惯打卡），且直接落地需要核对大量接口假设。作为参考有价值，不建议直接替换当前工程。

### 10.3 mimo 意见要点

- 强调项目约束不可违背：
  - 核心功能稳定优先。
  - 重复规则保持简单，不扩展复杂自定义规则。
  - 存储层 `storage.next_occurrence` 等稳定接口不宜大改。

### 10.4 豆包意见要点

- **布局**：主张双栏（左列表+右日历/详情），认为列表应为主导。
- **功能扩展**：自定义重复规则、数据备份/恢复、多主题切换（深色/极简白）、悬浮球、托盘角标。
- **皮肤**：建议主题系统，支持用户自定义。

**批判性评价**：双栏方案与核心流程冲突；自定义重复规则、数据备份等属于扩展功能，不应在当前阶段做；皮肤/主题建议被吸收。

### 10.5 综合决策

| 意见来源 | 采纳 | 未采纳 |
|----------|------|--------|
| ds | 三栏布局、点击事件修复、选中态强化 | 右栏默认隐藏 |
| hy | 三栏布局、长期任务分型思路、日历圆点、顶栏添加框 | 完整代码包直接替换、所有长期任务默认习惯打卡 |
| mimo | 约束优先、不改动稳定层 | - |
| 豆包 | 皮肤/主题系统、用户自定义皮肤方向 | 双栏布局、自定义重复规则、数据备份/恢复、悬浮球 |
