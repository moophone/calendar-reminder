## 2. 现状基线：真实工程到底有什么

### 2.1 技术栈与运行形态

【现状】

- Python 3.13 + PyQt6（工程内唯一第三方依赖），SQLite 标准库，无网络服务
- 本地 LLM：Qwen3-1.7B 经 llama.cpp 预编译运行时（llama-server + GBNF 约束输出），模型文件在 `models/`，体积约 1.8GB；不可用时整条解析链路自动降级，不影响基础功能
- 单进程常驻：**主窗口 + 桌面悬浮球 + 系统托盘 + 后台提醒引擎**四件套同时存在
- [main.py](file:///D:/1a个人/软件设计/日历提醒工具/v1.0/main.py#L174) 设置 `setQuitOnLastWindowClosed(False)`：关主窗口只是隐藏，程序靠球/托盘常驻；真正退出走托盘菜单或小球右键
- 首次运行（settings 无 `installed=1`）：创建桌面图标、默认开启开机自启、300ms 后主动显示主窗口
- 启动 900ms 后执行首轮强制提醒检查（普通通道 + 长期每日通道），本地模型在后台预加载

### 2.2 真实数据库（4 张表，不是 v1.0 文档画的那版）

数据库文件：`v1.0/data/calendar.db`。建表与迁移见 [storage.py L100-L139](file:///D:/1a个人/软件设计/日历提醒工具/v1.0/storage.py#L100-L139)。

```sql
tasks(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title       TEXT NOT NULL,
  detail      TEXT DEFAULT '',          -- 备注/详情（纯文本）
  due_date    TEXT,                     -- YYYY-MM-DD，可空（长期任务允许无目标日）
  due_time    TEXT,                     -- HH:MM，可空
  recur       TEXT DEFAULT 'none',      -- none/daily/weekly/monthly/yearly
  lead_days   TEXT DEFAULT '1,3',       -- 逗号分隔的提前预警天数
  status      TEXT DEFAULT 'pending',   -- pending/done
  created_at  TEXT NOT NULL,
  completed_at TEXT,
  task_type   TEXT DEFAULT 'short',     -- 只有 short / long 两个值
  last_notified_at DATE                 -- 长期任务"每日通道"当日已弹标记
)
journals(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id INTEGER NOT NULL,
  content TEXT NOT NULL,                -- 自由文本历程（也承载打卡，见 §6.2）
  created_at TEXT NOT NULL,
  FOREIGN KEY(task_id) REFERENCES tasks(id) ON DELETE CASCADE
)
reminder_log(
  task_id INTEGER NOT NULL,
  log_date TEXT NOT NULL,               -- 提醒针对的周期实例日期
  shown_at TEXT NOT NULL,
  PRIMARY KEY (task_id, log_date)       -- 同周期实例只弹一次
)
settings(key TEXT PRIMARY KEY, value TEXT)
```

- 唯一索引：`idx_tasks_type_due ON tasks(status, task_type, due_date)`
- 迁移机制【现状】：[migrate()](file:///D:/1a个人/软件设计/日历提醒工具/v1.0/storage.py#L54-L97) 幂等——task_type、last_notified_at 两列就是历史上用 `ALTER TABLE ADD COLUMN` 加出来的；due_date 放开 NOT NULL 用的是 SQLite 官方"建新表→搬数据→改名"流程。**v2.0 唯一的新增列直接沿用这套成熟机制（§6.4）。**
- 连接：单连接 + `threading.RLock`，`check_same_thread=False`（60 秒后台轮询与 UI 共用）

### 2.3 逻辑层真实能力（mimo 冻结的就是这一层）

【现状】storage 提供的完整能力（签名见 §11 契约表）：

- CRUD：add_task / **update_task（已存在，9 字段白名单）** / delete_task（级联清 journals、reminder_log）/ get_task / all_tasks
- 完成语义：complete_task —— 一次性任务置 done；**重复任务不置 done，而是把 due_date 锚点推进到下一周期并清空 reminder_log**；reopen_task
- 重复规则：next_occurrence(due: date, recur: str, ref: date)（入参是 date 不是字符串）、occurs_on(due, recur, day)
- 面板/日历查询：panel_tasks（全部 long + 7 天内 short）、tasks_on(day)、month_has_task(year, month)
- 长期每日通道：long_tasks_for_daily（有目标日、last_notified_at < 今天）、mark_daily_notified
- 历程：add_journal / journals_of（按 id 倒序）
- 去重：already_reminded / mark_reminded（INSERT OR IGNORE）/ clear_reminded（snooze 时删记录）
- 设置：get_setting / set_setting（UPSERT）

【现状】提醒引擎 [reminders.py](file:///D:/1a个人/软件设计/日历提醒工具/v1.0/reminders.py)：

- 5 种提醒种类：`today` / `overdue` / `lead` / `recur_today` / `long`
- ReminderItem(task: dict, eff_date: date, kind: str, days: int)，属性 log_key = (task_id, eff_date ISO)
- human_explain(task) 已产出完整人话文案（逾期 N 天/明天到期/每周重复·今天就轮到/含 due_time/含提前预警说明），主界面与弹窗共用
- collect_due：**显式跳过 long 与无日期任务**；逾期只有非重复任务会产生（重复任务经 next_occurrence 归一后 eff 永远不早于今天）；排序 overdue > today > recur_today > lead
- collect_long_daily：长期任务独立的每日一次通道
- today_brief → (n_today, n_overdue) 供悬浮球角标；**注意它不排除 long**（长期任务目标日=今天也计入今天件数），逾期只统计非重复任务——这是真实口径，v2.0 不改
- ReminderEngine：QTimer 60 秒轮询；信号 items_ready(list)、ticked()；snooze 只存内存 dict（重启后重新提醒，代码注释明确这是有意为之）；发信号前先写 reminder_log，防止轮询与开机首轮重复弹

【现状】四阶段 AI 解析链路（v1.0 工程最差异化的资产，v1.0 设计稿几乎没提）：

- P0 text_parser：规则解析（11 项测试覆盖），本地零成本，绝大多数中文时间表达在此命中
- P1 llm_fallback：本地 Qwen3-1.7B（llama-server，GBNF 保证 JSON 结构），进程不可用即跳过
- P2 parse_pipeline：候选匹配与终判（13 项测试覆盖）
- P3：入库前终检（置信度/冲突字段裁定）
- 结果在 ImportDialog 中以六列表格给用户确认：解析结果两档标色、可全选/反选、可绑定基准日期 bind_date

### 3.1 【沿用】经核实仍然成立、v2.0 原样保留的部分

## 6. 数据契约：零破坏增量方案

### 6.1 原则

1. 旧表、旧列、旧枚举值（short/long、pending/done、五种 recur）一个不动。
2. 全库只允许一处增量：tasks 增加一列**纯展示用途**的 `display_kind`。
3. 不新增打卡表、不新增历史表、不新增标签表。
4. 习惯打卡数据落在现有 journals 表；连续天数由视图模型从 journals 派生，不物化、不存冗余。

### 6.2 长期任务两种展示形态（替代 v1.0 的四分型）

【现状】真实 task_type='long' 同时承担两类东西：有明确目标日的倒计时目标（如 SAIS 2027-03-01、12 月竞赛），以及无目标日或弱目标日的持续事项。两类的提醒通道完全相同（collect_long_daily 每日一次，仅当 due_date 非空），**差别只在卡片长相和主动作**。

【v2.0】因此只区分"展示形态"，存储语义不变：

| 展示形态 display_kind | 对应真实数据 | 卡片长相 | 卡片主动作 | 提醒行为 |
|----------------------|--------------|----------|------------|----------|
| `goal`（目标倒计时，**long 的默认形态**） | task_type='long' | 大字号倒计时 + 目标日 + 进度（已过天数/总天数，仅当有 due_date） | "记一笔"（写历程） | 完全沿用 collect_long_daily |
| `habit`（每日习惯） | task_type='long' | 连续天数 + 最近 7 日打卡点 + "今日打卡"按钮 | add_journal 打卡 | 同上；**无 due_date 的习惯不产生每日弹窗**（真实引擎限制，见下"诚实限制"） |
| （无第三形态） | — | — | — | — |

规则：

- display_kind 仅对 task_type='long' 有意义；short 行该列恒为 NULL，UI 忽略。
- 老数据迁移：所有现存 long 默认 'goal'（现状数据本来就是目标型，如 SAIS）。
- TaskDialog 中选"长期"后出现一个二选一片段："目标倒计时 / 每日习惯"，默认目标。编辑时可互改（只改展示列，不动任何日期数据）。
- 打卡即写历程：点"今日打卡"→ add_journal(task_id, content)，content 默认"打卡"（也可弹一行输入让用户写内容，复用现有历程输入框）。**同一天重复点击不插第二条**：先查 journals_of 当天是否已有记录（视图模型提供 has_checkin_today），已打卡则按钮置"今日已打卡 ✓"。
- 连续天数 streak 算法（视图模型，§7）：取该任务全部 journals 的 created_at 日期去重排序，从今天向昨天回溯连续段；今天没打卡不断链（从昨天起算），昨天断了才结束。**不硬编码"30 天网格"**：最近打卡点显示最近 14 天（2×7 周排），目标型不显示打卡网格。

**关于 registration（报名截止）的否决留痕**：它需要的全部能力——到期日、到期时刻、提前 N 天预警、当天弹窗——真实 due_time + lead_days('1,3') + KIND_LEAD/KIND_TODAY 已完整提供，"英语六级报名 12-15 18:00"在现引擎里就会提前 3/1 天和当天各提醒一次。原型中"报名"字样属于用户自定义标签，标签系统成本（新列/新表+编辑 UI+筛选）与其使用频率不匹配，列入 §14 后续候选。

**诚实限制（写进规格，开发时不许偷偷改引擎）**：无 due_date 的 habit 不会收到每日打卡弹窗（collect_long_daily 要求 due_date 非空）。要给习惯独立的"每晚提醒打卡"通道必须改 reminders 冻结层，v2.0 不做；用户给习惯填一个远期目标日即可获得每日通道——TaskDialog 在选"每日习惯"时对此给一句灰色说明。

### 6.3 完成语义三分支（复选框/按钮行为定义）

严格对齐真实 [complete_task](file:///D:/1a个人/软件设计/日历提醒工具/v1.0/storage.py#L249-L273)，UI 不得自创语义：

| 任务种类 | 中栏卡片上的动作 | 调用 | 数据结果 | 中栏反馈 |
|----------|------------------|------|----------|----------|
| 短期·不重复 | 复选框"完成" | complete_task(id) | status='done'，completed_at=now | 卡片淡出移至"已完成"折叠组；toast"已完成 · 可在已完成中撤销" |
| 短期·重复（daily/weekly/monthly/yearly） | 复选框"完成本次" | complete_task(id) | **仍 pending**；due_date 推进到 next_occurrence(明天起)；reminder_log 清空 | 卡片日期跳动到下一周期并重新分组；toast"已推进到 X月X日" |
| 长期·goal/habit | 无复选框；goal 为"记一笔"、habit 为"今日打卡" | add_journal | journals +1 | 打卡点点亮/streak+1；目标本身不结束 |
| 长期·彻底结束 | 仅在右栏详情区："标记完成（结束目标）" | complete_task(id)（long 且 recur=none 时走 done 分支） | status='done' | 进已完成组 |
| 任意已完成 | 已完成组内"重新打开" | reopen_task | status='pending'、completed_at=NULL | 回到对应分组 |

注：真实 complete_task 对重复任务的锚点推进以"明天"为 ref（today+1），保证今天完成后不会落在今天。规格照此实现，不自作聪明改成今天。

## 7. 视图模型层 viewmodel.py

### 7.1 定位

【v2.0】新增 `viewmodel.py`（扁平结构，与 storage.py 同级；若走 §10 拆包则放包内）。**零 PyQt import**，输入 storage 的 dict / reminders 的 ReminderItem，输出 dataclass，可纯 pytest 测试。它是 hy v7 最有价值的贡献，v2.0 采纳并按真实数据重新定义字段（hy 版未与真实库联调，字段不可直接照抄）。

### 7.2 TaskView 数据契约

```python
@dataclass(frozen=True)
class TaskView:
    id: int
    title: str
    detail: str
    task_type: str            # 'short' | 'long'（真实字段直传）
    display_kind: str | None  # 'goal' | 'habit' | None
    status: str               # pending | done

    # 日期语义（全部在这里算完）
    eff_date: date | None     # next_occurrence(due_date, recur, today)；无日期为 None
    due_time: str | None
    recur: str
    days: int | None          # (eff_date - today).days；None=无日期
    is_overdue: bool
    is_today: bool

    # 展示派生
    group: str                # §7.3 分组键
    badge: tuple[str, str] | None   # (文案, 语义色键名) 如 ("已逾期","urgent")
    explain: str              # 直接取 reminders.human_explain，禁止 UI 重拼
    cd_text: str              # 倒计时大字，如 "128" / "今天" / "已逾期 1 天"
    cd_unit: str              # "天" / "" （今天/逾期时单位为空）

    # 长期专用
    streak: int               # 连续打卡天数（short 恒 0）
    checkins_14d: list[bool]  # 最近 14 天打卡点阵（仅 habit 有意义）
    checked_today: bool
    journal_count: int
    progress: float | None    # goal：已过天数/总天数（0~1），无 due_date 为 None
```

构造入口建议：`build_views(today=None) -> list[TaskView]`（内部调 storage.all_tasks(True) + journals_of）、`build_views_for_day(day) -> list[TaskView]`（调 tasks_on）。性能说明：journals_of 每任务一次查询属 N+1，但真实任务量级（数十至数百）无压力；若日后上千，再在 storage 加批量接口（届时属冻结层演进，另行评审）。

### 7.3 分组口径与互斥优先级（修正 v1.0 文档的矛盾）

分组键与顺序（中栏自上而下）：

1. `overdue` 逾期 —— pending 且 task_type='short' 且 eff_date < today
2. `today` 今天 —— pending 且 short 且 eff_date == today（含 recur_today 当天）
3. `week` 7 天内 —— pending 且 short 且 1 <= days <= 7
4. `habit` 每日习惯 —— pending 且 long 且 display_kind='habit'
5. `goal` 目标倒计时 —— pending 且 long 且 display_kind='goal'（默认）
6. `later` 远期 —— pending 且 short 且 days > 7
7. `nodate` 未设日期 —— pending 且任意类型但 eff_date IS NULL
8. `done` 已完成 —— status='done'（折叠）

**关键决策（与真实提醒引擎的通道划分一致）**：

- 紧急度分组（1/2/3/6）只收 short；long 永远进 4/5，**不做跨组镜像卡**。因此不会出现 v1.0 伪代码里"今天截止的习惯消失"的歧义。
- long 在今天/逾期的紧急性通过**组内排序 + 强色徽标**表达：habit/goal 组内排序为"逾期置顶 → 今天 → 未来升序 → 无日期置底"，逾期/今天的长期卡借用 urgent/today 徽标色；同时真实 today_brief 角标本就会计入今天的 long（§2.3），球上数字与界面不打架。
- nodate 组是**对真实面板缺陷的补全**：现 panel_tasks 查询使"无日期短期任务"在主界面不可见（条件 long OR due_date<=horizon）。v2.0 中栏数据源改用 viewmodel 全量构建，nodate 组让这类任务可见。注明这是行为增强。
- 重复任务经 next_occurrence 归一后 eff_date 不早于今天，自然不会进 overdue——与 collect_due 的 KIND_OVERDUE 只给非重复任务同口径。
- 空组整组不渲染（组头也不显示）；done 组即使非空也默认折叠。

### 7.4 左栏筛选与日视图如何作用于分组

筛选不是另一套分组，而是对上述 8 组的**显示过滤**：

| 筛选项 | 显示的组 | 计数口径（角标数字） |
|--------|----------|---------------------|
| 全部待办（默认） | 1–7 全显，8 折叠 | 全部 pending 数 |
| 逾期 | 仅 1 | overdue 数 |
| 今天 | 仅 2 | today 数 |
| 7 天内 | 1+2+3 | 距今天 ≤7 天的 pending short 数（含逾期） |
| 长期 | 4+5 | 全部 pending long 数 |
| 已完成 | 仅 8（展开） | done 数 |

日视图（点日历日期 D）：中栏切换为"单日模式"，数据 = build_views_for_day(D)（底层 storage.tasks_on，含重复命中、无日期任务不出现），**不按 8 组分组**，按 due_time 升序平铺卡片，顶部为日期条（§8.7）。筛选与日视图互斥：进入日视图时左栏筛选高亮取消。

### 7.5 viewmodel 测试要求（新增，不依赖 Qt）

- 分组：逾期/今天/7天/远期/无日期/已完成各一，断言组归属与排序；
- 重复任务归一：昨天起 daily/weekly/monthly/yearly 的 eff_date 与组；
- long 不进紧急组、逾期 long 在长期组置顶；
- streak：连续 5 天有 journal、今天未打卡不断链、断一天后归零、同日两条 journal 只算一天；
- display_kind 缺失（模拟老库）：long 一律按 goal；
- cd_text 边界：0 天="今天"、-1="已逾期 1 天"、无日期="未设目标日"。

### 9.3 落地机制（不用 QFile、不引 qrc、不引皮肤库）

【v2.0】重构 style.py 为"色板 dict + QSS 模板函数"：

```python
THEMES = {
    "warm":   { ... 上表 20 键，值=现网常量... },
    "cool":   { ... },
    "forest": { ... },
    "dark":   { ... },
    "anime":  { ... },
}

def build_qss(name: str = "warm") -> str:
    c = THEMES.get(name, THEMES["warm"])
    return f"""
    * {{ font-family: "Microsoft YaHei UI", "Microsoft YaHei", "Segoe UI", sans-serif;
         font-size: 13px; color: {c['TEXT']}; outline: none; }}
    QWidget#rootBg {{ background: {c['BG']}; }}
    QWidget.card {{ background: {c['CARD']}; border-radius: 14px;
                    border: 1px solid {c['BORDER']}; }}
    /* ……其余规则与现有 QSS 一一对应，值全部改取 c[...]… */
    """

def apply_theme(app, name: str):
    app.setStyleSheet(build_qss(name))
    storage.set_setting("theme", name)
    # 通知自绘组件重绘（DotCalendar/TaskCard 点阵/FloatBall/托盘图标）
```

- 现有那条模块级 `QSS` 变量保留一个版本周期：`QSS = build_qss("warm")`，main.py 的 import 不需要立刻改；迁移完成后改启动行为：`apply_theme(app, storage.get_setting("theme", "warm"))`。
- 模块级 ACCENT 等 20 常量保留为 warm 别名，搬迁期间防止旧引用断裂。
- 主题切换后必须做三件事：setStyleSheet、向主窗/球发主题变更信号让 paintEvent 重绘、tray.setIcon(make_app_icon()) 重建托盘图标。
- 自绘代码（paintCell、make_app_icon、脉冲动画、点阵、进度条）一律从当前主题 dict 取色，禁止再出现硬编码暖纸色。

### 9.4 QSS 禁忌（踩坑前置）

1. 禁止裸 `QWidget { background-color: ... }`：会给按钮、弹窗、日历内部所有子控件刷底；底色只能挂 `QWidget#rootBg` 与 `.card` 等具名类（现网已验证的写法）。
2. QSS 不是 CSS：没有变量、没有 transition；阴影不用 box-shadow（需要层次用 1px BORDER 描边 + 可选 QGraphicsDropShadowEffect，仅给卡片，勿给动画项）。
3. QCalendarWidget 内部结构（`#qt_calendar_navigationbar`、`QAbstractItemView` 日期格、周末文字色）要单独写选择器，夜间主题尤其必须真机调；QToolTip 单独给样式。
4. 不混用 QPalette 与 QSS 两套换肤路径；如个别原生控件（日历导航按钮）QSS 覆盖不到，仅对该控件补 QPalette，并集中在 style.py 一处。
5. 所有 † 派生色上机后做文字/底色对比度检查（正文 ≥4.5:1，徽标白字 ≥3:1），不达标只调派生值，不偏移原型已有色。
6. 字体/圆角/间距令牌（13px 基准、9/14px 圆角、4/8/12/16 间距）继续写死在 QSS 模板中，不随主题变化；五套主题只换颜色。

## 15. 快速参考卡

- 存储：4 表不动，仅加 tasks.display_kind TEXT（long='goal'/'habit'，short=NULL）；迁移追加在 migrate()，幂等
- 分型：short/long 是真实类型；goal/habit 只是 long 的长相；registration 不存在
- 打卡：add_journal 一条记录；streak 从 journals.created_at 日期序列派生；今天不打卡不断链
- 完成：非重复→done；重复→推进锚点+清 reminder_log；long 结束只在右栏
- 分组：overdue/today/week/habit/goal/later/nodate/done；紧急组只收 short，long 在本组内置顶加色
- 点击：QListWidget + setItemWidget + itemClicked；卡片按钮是真按钮；删除 TaskCard 的鼠标补丁
- 日历：QCalendarWidget + paintCell 不动；点日期=日视图（tasks_on），空天有空态
- 弹窗：四弹窗功能对账表逐项搬；非模态/snooze 内存 10 分钟/弹窗单例不改
- 主题：THEMES dict（5×20）+ build_qss(name) + apply_theme；warm 列=现网值；settings key='theme'
- 冻结：storage/reminders/text_parser/parse_pipeline/llm_fallback/countdown 不改签名语义；唯一功能改动=update_task 白名单加一列，需评审
